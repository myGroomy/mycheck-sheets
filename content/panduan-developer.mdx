# Panduan Developer

Panduan onboarding untuk developer yang melanjutkan mycheck. Baca bersama
spesifikasi di root repository; panduan ini merangkum struktur dan perilaku
implementasi yang ada, bukan menggantikan spesifikasi.

## Mulai dari dokumen acuan

Urutan prioritas dan aturan kerja berada di `AGENTS.md`. Dokumen lain:

1. `PRD.md` perilaku produk dan aturan bisnis.
2. `DATABASE_SCHEMA.md` struktur Google Sheets (Registry + spreadsheet cabang).
3. `TRD.md` keputusan arsitektur dan teknis.
4. `APP_FLOW.md` layar dan alur UX.
5. `IMPLEMENTATION_PLAN.md` tahapan implementasi.
6. `TESTING.md` kriteria verifikasi.
7. `UI-UX.md` panduan visual dan responsif.

<Callout type="warning">
  Spesifikasi saat ini memuat sejumlah layar dan pekerjaan berstatus rencana.
  Sebelum melanjutkannya, periksa route, handler, schema, dan tes yang benar-benar
  ada. Jika dokumen bertentangan dengan implementasi atau instruksi kerja,
  hentikan perubahan terkait dan minta keputusan; jangan menyimpulkan sendiri.
</Callout>

## Arsitektur dan Struktur Repository

Single project Next.js di root repo. **Bukan monorepo.**

```text
mycheck/
  app/                    # Next.js App Router pages, layouts, API routes
  components/             # UI petugas, admin, incident, report, komponen bersama
  lib/
    google/               # Google Sheets API client, branch-schema, cache
    store.ts              # Lapisan akses data (filter/list/insert/update)
    session.ts            # Cookie HMAC-SHA256 session management
    api-auth.ts           # Helper otorisasi untuk API route
    page-auth.ts          # Helper otorisasi untuk Server Component
    admin/                # Template service, sensitive action, settings catalog
    ...
  scripts/                # Setup registry, branch, seed admin
  docs/                   # Dokumentasi MDX (file ini)
  public/                 # Aset PWA
```

Tidak ada `apps/` atau `packages/`. API berada pada
`app/api/**/route.ts`. Data browser melewati Next.js server/API; akses
langsung browser ke Google Sheets tidak diperbolehkan.

## Setup Lokal

Gunakan Node.js 22.x dan npm:

```bash
npm install
npm run dev
```

Aplikasi berjalan pada port 3000 secara default. Siapkan environment lokal
terlebih dahulu; jangan menaruh nilai rahasia di source code, issue, log,
screenshot, atau file yang dikomit.

### Environment

| Variabel | Pemakaian |
| --- | --- |
| `REGISTRY_SPREADSHEET_ID` | ID spreadsheet Registry (global). |
| `GOOGLE_SA_EMAIL` | Email service account Google. |
| `GOOGLE_SA_PRIVATE_KEY` | Private key service account (newline escaped). |
| `GOOGLE_DRIVE_FOLDER_ID` | ID folder Google Drive untuk storage foto. |
| `SESSION_SECRET` | Secret untuk HMAC-SHA256 session token. |
| `PIN_PEPPER` | Pepper untuk verifikasi PIN (disimpan di sheet, bukan hash). |
| `CRON_SECRET` | Otorisasi endpoint cron bila digunakan. |

<Callout type="warning">
  Jangan menampilkan atau mengirim isi `.env`, `.env.local`, secret sesi,
  pepper PIN, atau private key ke layanan eksternal. Jangan pernah menempatkan
  rahasia di kode klien, log, atau respons.
</Callout>

### Perintah Kerja

Dari root repo:

```bash
npm run dev              # Dev server (port 3000)
npm run build            # Production build
npm run typecheck        # TypeScript check
npm run lint             # Oxlint
npm run setup:registry   # Inisialisasi Registry spreadsheet
npm run setup:branch     # Daftarkan cabang baru
npm run seed:admin       # Buat admin pertama
```

Untuk mendaftarkan cabang:

```bash
npm run setup:branch -- <Cabang_ID> <Nama> <Spreadsheet_ID> [Timezone] [Kode]
```

Contoh:

```bash
npm run setup:branch -- CAB01 Cabang_Jakarta 1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms Asia/Jakarta JKT
```

## Aturan Data (Google Sheets)

<Callout type="warning">
  **`valueInputOption: 'RAW'` wajib** untuk semua tulisan. Dengan
  `USER_ENTERED`, Sheets mengurai `"2026-10-08"` menjadi serial angka `46303`
  dan `"true"` menjadi boolean merusak `shift_date`, `tab_month`, dan nilai
  centang.
</Callout>

Aturan wajib saat bekerja dengan Google Sheets:

1. **Baca/tulis berdasarkan nama kolom** lewat `lib/store.ts`, bukan urutan.
2. **Boolean** ditulis sebagai string `'TRUE'`/`'FALSE'` dibaca lewat `asBool()`.
3. **Tidak ada transaksi.** Operasi lintas sheet tidak atomik lakukan
   compensating action bila gagal.
4. **Tidak ada unique index.** BR-01 (satu shift per definisi+tanggal) dijaga
   pengecekan aplikasi sebelum insert.
5. **Tidak ada row lock.** BR-12 (aksi pertama menang) dijaga pengecekan state
   sebelum update.
6. **Tidak ada penghapusan baris bisnis.** Hanya ubah status/is_active/void.
7. **Waktu** disimpan sebagai string ISO UTC. Tampil sesuai zona waktu cabang.
8. **ID** memakai ULID, dibuat di aplikasi dengan `ulid`.
9. **Idempotency**: setiap aksi dari klien membawa `client_action_id`, dicek di
   `EntryLogs.client_action_id` sebelum menulis.
10. **Baca Sheet itu mahal.** Pakai cache TTL (`lib/google/cache.ts`) dan
    `values.batchGet` (`filterRowsMulti`) bila membaca >1 sheet.
11. **Mutasi Registry/Users wajib** memanggil `resetRegistryCache()` /
    `resetUsersCache()`.
12. **Verifikasi PIN admin wajib** membaca sheet langsung, bukan cache.

### Contoh Akses Data

```typescript
import { listRows, filterRows, findRow, insertRow } from '@/lib/store';

// Baca semua baris
const shifts = await listRows(spreadsheetId, 'ShiftInstances');

// Filter dengan predicate
const open = await filterRows(spreadsheetId, 'ShiftInstances', (r) => r.status === 'open');

// Cari satu baris
const user = await findRow(spreadsheetId, 'Users', 'Username', 'budi');

// Insert (valueInputOption: 'RAW' diterapkan di sheets.ts)
await insertRow(spreadsheetId, 'ShiftInstances', {
  id: ulid(),
  shift_definition_id: 'shift_pagi',
  shift_date: '2026-10-08',
  tab_month: '2026-10',
  status: 'open',
});
```

## Pola Implementasi

### API dan Autentikasi

- API terlindungi menggunakan helper di `lib/api-auth.ts`; cek role dan akses
  cabang di server pada **setiap** request.
- UI yang menyembunyikan tombol bukan pengganti otorisasi server.
- Validasi input mengikuti schema Zod.
- Cookie sesi: HttpOnly, Secure, SameSite=Lax. Pasang CSRF (custom header
  `X-Requested-With`).
- Pesan error kepada pengguna tidak membocorkan detail database/Google.

### Audit Log

- Audit log append-only dengan hash chain, ditulis ke tab bulanan
  `AuditLog_<YYYY-MM>`.
- Hash chain di-reset per tab bulan (bukan global).
- Aksi sensitif admin wajib alasan + konfirmasi PIN dan tercatat di audit log.

## Fitur yang Tersedia

- Login username + PIN 6 digit, cookie sesi HMAC-SHA256, validasi sesi server.
- Beranda petugas dengan daftar cabang/shift yang dapat diakses.
- Buka/gabung shift, checklist bersama, progress dan peserta, penutupan shift
  oleh PJ dengan PIN.
- Incident: daftar, pembuatan dengan foto, detail dan catatan lanjutan.
- Laporan shift dan halaman laporan publik `/r/[token]`.
- Panel admin untuk cabang, akun, shift/template, kategori incident, laporan,
  pengaturan, dan audit log.

<Callout type="info">
  Daftar di atas adalah orientasi, bukan jaminan bahwa seluruh perilaku PRD sudah
  selesai. Periksa setiap route dan jalankan pengujian terkait sebelum
  memperluasnya.
</Callout>

## Hal yang Perlu Diverifikasi oleh Developer Berikutnya

1. **Paksa ganti PIN:** route `/ganti-pin` tersedia, tetapi verifikasi bahwa
   login dengan `mustChangePin` benar-benar mengarahkan dan membatasi pengguna.
2. **Polling progress:** ukur endpoint `/api/shifts/[id]/progress` dengan
   beberapa client. Pastikan fokus/visibility/interval dan refresh setelah aksi
   tidak menumpuk request.
3. **Uji lintas role/cabang:** uji akses API langsung, bukan hanya tampilan UI.
   Uji aksi bersamaan BR-01 dan BR-12 memakai dua akun/permintaan paralel.
4. **Kesesuaian spesifikasi:** bandingkan fitur yang akan dikerjakan dengan
   status di `IMPLEMENTATION_PLAN.md`, kode saat ini, dan `TESTING.md`.
