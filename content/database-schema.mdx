# Database Schema — mycheck

<Callout type="warning">
  mycheck **tidak menggunakan SQL database**. Data disimpan di **Google Sheets**
  yang diakses via API sebagai service account. Tidak ada migration, tidak ada
  ORM, tidak ada transaksi. Sumber kebenaran struktur adalah spreadsheet
  `Template_cabang_mycheck`; definisi kolom di kode ada di
  `lib/google/branch-schema.ts`.
</Callout>

## Konsep Inti

**Cabang = spreadsheet.** Tidak ada tabel `branches` dan tidak ada kolom
`branch_id`. Satu spreadsheet per cabang, jadi sudah secara implisit berada di
spreadsheet yang benar.

Ada dua spreadsheet yang berbeda sifat:

| | **Registry** | **Spreadsheet cabang** |
|---|---|---|
| Jumlah | 1 (global) | 1 per cabang |
| Isi | cabang, user, setting global, share token | template shift + data operasional cabang |
| Konvensi kolom | **PascalCase** (`Cabang_ID`, `Nama_Cabang`) | **snake_case** (`shift_date`, `created_at`) |
| Env | `REGISTRY_SPREADSHEET_ID` | kolom `Spreadsheet_ID` di Registry |

Konvensi nama berbeda antara Registry (PascalCase, mengikuti stokis) dan
spreadsheet cabang (snake_case). Ini disengaja — jangan disamakan.

## 1. Registry

Satu spreadsheet global untuk semua cabang.

### Sheet `Daftar_Cabang`

Daftar semua cabang yang terdaftar.

| Kolom | Tipe | Keterangan |
|---|---|---|
| `Cabang_ID` | string | PK. Sama dengan `Kode`. |
| `Nama_Cabang` | string | Tampil di UI. |
| `Kode` | string | Kode unik cabang. |
| `Timezone` | string | IANA, mis. `Asia/Jakarta`. Menentukan tanggal shift. |
| `Spreadsheet_ID` | string | ID spreadsheet cabang. Kosong = cabang nonaktif. |
| `Folder_Drive_ID` | string | Folder Drive untuk unggah foto. |
| `Aktif` | bool | Hanya cabang aktif yang bisa diakses. |

<Callout type="info">
  Cabang dibuat **nonaktif**. Wajib diisi `Spreadsheet_ID` dulu sebelum bisa
  diaktifkan — API menolak mengaktifkan cabang tanpa spreadsheet.
</Callout>

### Sheet `Users`

Semua pengguna (admin & petugas).

| Kolom | Tipe | Keterangan |
|---|---|---|
| `User_ID` | string | PK, format `U-<timestamp>`. |
| `Username` | string | Unik, dipakai sebagai identitas sesi. |
| `PIN` | string | **Plaintext** (6 digit). Pinjaman keamanan yang disepakati. |
| `Nama` | string | Nama tampilan. |
| `Role` | string | `admin` \| `petugas`. |
| `Cabang_ID` | string | ID cabang dipisah koma. **Kosong untuk admin** (admin akses semua). |
| `Aktif` | bool | |
| `Must_Change_Pin` | bool | Diset `TRUE` saat admin reset PIN user. |
| `Created_At` | string | ISO UTC. |

<Callout type="warning">
  Tidak ada tabel `user_branch_access` — akses cabang disimpan di kolom
  `Cabang_ID`. Tidak ada `pin_fail_attempts` (tidak ada lockout/rate limiting).
</Callout>

### Sheet `Settings_Global`

`Key` | `Value`. Tipe (`int`/`bool`/`string`/`text`) **tidak** disimpan di sheet —
katalognya ada di kode: `lib/admin/settings-catalog.ts`. Ini konsekuensi sheet
yang hanya punya dua kolom.

### Sheet `Share_Tokens`

Token laporan publik. Kolom: `id`, `report_id`, `branch_id`, `token`,
`created_by`, `created_at`, `expires_at`, `revoked_at`, `access_count`,
`last_accessed_at`, `share_note`, `visibility`.

<Callout type="info">
  Token disimpan apa adanya (bukan hash) agar route publik bisa mencarinya dengan
  satu pembacaan sheet.
</Callout>

### Sheet `Template_Referensi`

`Template_Spreadsheet_ID` — pointer ke template master.

## 3. Cara Membaca Data

Aplikasi membaca data lewat **`lib/store.ts`** (filter/list/insert/update) yang
berada di atas **`lib/google/sheets.ts`**. Aturan penting:

<Callout type="warning">
  **`valueInputOption: 'RAW'` wajib** untuk semua tulisan. Dengan
  `USER_ENTERED`, Sheets mengubah `"2026-10-08"` menjadi `46303` dan `"true"`
  menjadi boolean — merusak `shift_date`, `tab_month`, dan nilai centang.
</Callout>

### Aturan Wajib Dijaga

1. **Baca/tulis berdasarkan nama kolom**, bukan urutan. Header sheet adalah skema.
2. **Boolean** ditulis sebagai string `'TRUE'`/`FALSE'`, dibaca lewat `asBool()`.
3. **Tidak ada transaksi.** Operasi lintas sheet tidak atomik. Kalau sebagian
   gagal, lakukan kompensasi atau kembalikan seperti semula.
4. **Tidak ada unique index.** BR-01 (satu shift per definisi+tanggal) dijaga
   pengecekan aplikasi sebelum insert — pada request paralel masih mungkin ada
   race (dulu dijaga advisory lock).
5. **Tidak ada row lock.** BR-12 (aksi pertama menang) dijaga pengecekan state
   sebelum update.
6. **Hapus baris secara fisik** hanya boleh untuk operasi admin yang memang
   perlu menghapus konfigurasi. Lifecycle bisnis (shift, incident, laporan)
   **tidak** menghapus baris — hanya ubah status.
7. **Waktu** disimpan sebagai string ISO UTC. Tampil sesuai zona waktu cabang.
8. **ID** memakai ULID, dibuat di aplikasi dengan `ulid`.
9. **Idempotency**: setiap aksi dari klien membawa `client_action_id`, dicek di
   `EntryLogs.client_action_id` sebelum menulis.
10. **Semua operasi baca Sheet itu mahal** (1 panggilan API). Pakai cache TTL
    (`lib/google/cache.ts`) dan `values.batchGet` (`filterRowsMulti`) bila
    membaca >1 sheet.
11. **Mutasi ke Registry/Users wajib** memanggil `resetRegistryCache()` /
    `resetUsersCache()`.
12. **Verifikasi PIN admin** (`lib/admin/sensitive-action.ts`) **wajib** membaca
    sheet langsung, bukan cache — supaya PIN yang baru di-reset tidak kedaluwarsa.

### Contoh Kode

```typescript
// lib/store.ts — Lapisan akses data berbasis Google Sheets
import { listRows, filterRows, findRow, insertRow } from '@/lib/store';

// Baca semua baris dari sebuah sheet
const shifts = await listRows(spreadsheetId, 'ShiftInstances');

// Filter dengan predicate
const activeShifts = await filterRows(spreadsheetId, 'ShiftInstances', (row) =>
  row.status === 'open'
);

// Cari satu baris berdasarkan kolom
const user = await findRow(spreadsheetId, 'Users', 'Username', 'budi');

// Insert baris baru (valueInputOption: 'RAW' diterapkan di sheets.ts)
await insertRow(spreadsheetId, 'ShiftInstances', {
  id: ulid(),
  shift_definition_id: 'shift_pagi',
  shift_date: '2026-10-08',
  tab_month: '2026-10',
  status: 'open',
});
```

## 4. Snapshot & Audit

- **Snapshot template** disimpan sebagai JSON di `ShiftInstances.template_snapshot`
  (`snapshot_encoding` = `json`). Perubahan template setelah shift dibuka tidak
  memengaruhi shift yang sedang berjalan (BR-05).
- **Hash chain audit** dihitung di dalam satu tab bulanan, jadi chain **di-reset
  setiap ganti bulan** — bukan global seperti di PostgreSQL. Ini perbedaan yang
  diterima, bukan bug.

## 5. Menambah Kolom

1. Ubah header di Registry atau di seluruh spreadsheet cabang.
2. Update `lib/google/branch-schema.ts` (`STATIC_SHEETS` atau `MONTHLY_SHEETS`).
3. Update pemanggilnya di `lib/store.ts` / `lib/admin/template-service.ts`.
4. Tidak ada migrasi — tapi **penyesuaian** ke spreadsheet cabang lama wajib
   dilakukan manual, karena kode tidak menambah kolom yang belum ada.
