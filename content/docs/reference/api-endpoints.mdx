# Endpoint API

Semua path di bawah memakai prefix `/api`. Endpoint terproteksi memerlukan
cookie sesi yang valid; route admin juga membatasi peran. Hak akses cabang
tetap divalidasi di server. Route publik dan pemeriksaan operasional ditandai
terpisah. Rincian payload dapat berubah; handler route adalah sumber kebenaran.

## Sesi dan operasional petugas

| Path | Metode | Akses / fungsi |
| --- | --- | --- |
| `/auth/login` | `POST` | Masuk dengan username dan PIN. |
| `/auth/me` | `GET` | Informasi sesi aktif. |
| `/auth/change-pin` | `POST` | Mengganti PIN akun. |
| `/auth/logout` | `POST` | Keluar dari sesi saat ini. |
| `/auth/logout-all` | `POST` | Menghapus cookie browser pemanggil; tidak mencabut token stateless di perangkat lain. |
| `/beranda` | `GET` | Data beranda sesuai sesi dan akses cabang. |
| `/shifts` | `GET` | Daftar shift yang dapat diakses. |
| `/shifts/open` | `POST` | Membuka shift. |
| `/shifts/[id]/join` | `POST` | Bergabung ke shift. |
| `/shifts/[id]/entries` | `POST` | Mengirim aksi checklist. |
| `/shifts/[id]/progress` | `GET` | Membaca progress shift. |
| `/shifts/[id]/close` | `POST` | Menutup shift oleh PJ. |
| `/shifts/[id]/handover` | `POST` | Mengirim handover. |
| `/shifts/[id]/handover-prev` | `GET` | Membaca handover sebelumnya. |
| `/handovers/[id]/ack` | `POST` | Mengonfirmasi handover telah dibaca. |

### Lifecycle arsip dan penghapusan konfigurasi

- Daftar admin menyediakan mode **Aktif** dan **Arsip**; data arsip dapat dipulihkan.
- `DELETE` pada `/admin/branches/[id]` dan `/admin/users/[id]` selalu ditolak (`409`). Cabang dan akun dipertahankan untuk menjaga histori serta atribusi.
- Untuk `/admin/shifts/[id]`, `/admin/sop-categories/[id]`, `/admin/checklist-points/[id]`, `/admin/handover-fields/[id]`, dan `/admin/incident-categories/[id]`, konfigurasi harus diarsipkan terlebih dahulu. Penghapusan hanya berhasil bila pemeriksaan server memastikan tidak ada shift historis, dependensi, atau referensi data; pemeriksaan yang gagal tidak boleh dianggap aman.
- Endpoint daftar konfigurasi menyediakan `canDelete` atau indikator histori/dependensi untuk mengendalikan visibilitas aksi hapus di UI. Nilainya dihitung dengan fungsi yang sama seperti route `DELETE` (`lib/admin/lifecycle-policy.ts`), sehingga tidak ada dua sumber kebenaran yang bisa berbeda.
- Route `DELETE` tetap mengulang pemeriksaan pada request itu sendiri dengan pembacaan segar, dan menulis audit log (`delete_shift_definition`, `delete_sop_category`, `delete_checklist_point`, `delete_handover_field`, `delete_incident_category`) bila baris benar-benar terhapus.

## Pemeriksaan sistem

| Path | Metode | Akses / fungsi |
| --- | --- | --- |
| `/health` | `GET` | Memeriksa dependensi aplikasi. |
| `/cron/verify` | `GET` | Memeriksa secret cron; bukan verifikasi hash-chain audit. |

Gunakan route handler terkait untuk memeriksa bentuk request/response, validasi,
kode status, dan otorisasi terbaru. Jangan menganggap path admin dapat diakses
hanya karena tombolnya terlihat atau tersembunyi di UI.
